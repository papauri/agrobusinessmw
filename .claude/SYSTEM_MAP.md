## 3. USSD menu tree (`ussd/menus.php` + `ussd/logic.php`)

Entry: `ussd/index.php:10-17` requires `config.php`, `menus.php`, `helpers.php`,
`weather.php`, `logic.php`, then calls `process_ussd()`.

Navigation is stack-based, replayed from Africa's Talking's accumulated `text` param each
request (`ussd/logic.php:25-124`). Language ('1'=en,'2'=ci) is level 0; district lists and
crop lists are paginated 3 pages of 8 (`ussd/menus.php:14-44`, district IDs mapped
`ussd/logic.php:7-11`).

```
Level 0: Language select (menus.php:7-10)
└─ Level 1: Main menu (menus.php:14-15) — options 1-9, 0=back, 00=change language
   ├─ 1 Crop Prices (logic.php:183) → sub-menu (menus.php:48-49)
   │    ├─ 1 By District → district pages → get_prices_by_district() (helpers.php:139) reads crops+crop_prices
   │    └─ 2 By Crop → 9-crop list (menus.php:54-56) → district pages → get_prices_by_crop_district() (helpers.php:173)
   ├─ 2 Market Insights (logic.php:187) → district pages → market_insights table (logic.php:256-257)
   ├─ 3 Pest Control (logic.php:191, 306-312, 358-371) → crop select (3 crops) → district pages → pest_control_tips table
   ├─ 4 Farming Practices (logic.php:191, 314-320, 374-388) → crop select → practice type (Planting/Harvesting/Growing, menus.php:118-120) → farming_best_practices table
   ├─ 5 Community Q&A (logic.php:187, 264-272) → district pages → community_qa table (logic.php:267) — READ CONFIRMED
   ├─ 6 Farming Info (logic.php:195-206) → basic_farming_info table, no district needed
   ├─ 7 Find Sellers (logic.php:187, 274-289) → district pages → sellers+seller_contact_details+ratings (logic.php:276-281) — ratings READ CONFIRMED
   ├─ 8 Find Buyers (logic.php:187, 291-302) → district pages → buyers+buyer_contact_details
   ├─ 9 Weather (logic.php:208-210, 234-243) → district pages → get_weather_forecast() (ussd/weather.php:4), coords from ussd/config.php ($district_coords) — SEPARATE from app.js's own districtCoords (doc-drift note in §7)
   ├─ 0 Back → language selection (not exit)
   └─ 00 Change language toggle (logic.php:140-150), persisted per-session via ussd/sessions/*.json
```

Note (`ussd/menus.php:123-127`, verified in-code comment): a duplicate, mis-indexed
district-coordinate table used to live in `menus.php` (IDs 17-24 shifted by one) and
silently overrode the correct one in `config.php` because of include order — root cause of
the bug fixed in commit `fd12ace` ("fix(weather): resolve district coordinates by name, not
mismatched id"). The comment now forbids redefining it there.

## 5. Gaps

- **`ratings` has no writer** — read in 2 places (sellers listing + USSD), never written.
  Either ratings are seeded manually/by a process outside this repo, or the rating
  submission feature was never built. Blocks any "submit a rating" UI from having a
  backend today. **Actionable**: add a `submit_rating` action or confirm it's out of scope.
- **`community_qa` has no writer and no web reader** — USSD-only, read-only. If Q&A is
  meant to be user-submitted, that path doesn't exist. **Actionable**: same as above, or
  confirm it's admin-seeded only and drop from any "interactive" roadmap.
- **`crop_prices` action (`api.php:424`) has no caller** anywhere in the repo (grepped
  `.php`/`.js` for `action=crop_prices`, zero hits). Superseded by `dual_crop_prices`
  (`api.php:1082`), which layers FEWS + community data over the same `crop_prices` table.
  Safe to deprecate/remove pending confirmation nothing external (e.g. a mobile client)
  calls it.
- **`price_review_list` (`api.php:1287`) and `price_review` (`api.php:1319`) have no
  caller.** `admin/index.php` has its *own* inline crowdsourced-price review form
  (`admin/index.php:128-130` handling `$_POST['price_review_id']`) that does not go
  through api.php at all. These two actions look like a newer, parallel admin UI that was
  never wired up, or an abandoned refactor. **Actionable**: either wire an admin UI to
  them and retire the inline form, or delete the dead actions.
- **`test_email` (`api.php:1360`) has no caller** — manual ops/debug endpoint only. Low
  risk, but it's a live X-Admin-Token-gated action with no product surface.
- **`onboarding_applications`, `markets` tables have no `CREATE TABLE` anywhere** — not in
  `p601229_AgroBusiness_MW.sql`, not lazily created in any PHP file. They must already
  exist in the live production DB. The schema dump is **out of date relative to
  production** — a real risk for anyone provisioning a fresh environment from the SQL
  file alone (register/status/prices pages would fail outright).
- **`farming-guide.php`** has no matching api.php action (verified: no `farming_guide`
  case in the 22-action switch). `app.js:983-985` has a `loadFarmingGuide()` state
  handler, so the page likely renders static/hardcoded content client-side — unverified
  without reading the function body, flagged as **[inferred]**.

## 6. Dead code

- **Duplicate `admin_users` table bootstrap** — `api.php:325` and `admin/index.php:38`
  both run near-identical `CREATE TABLE IF NOT EXISTS admin_users (...)` + seed logic.
  Hygiene: consolidate into one shared include to avoid drift between the two schemas if
  either is edited later.
- **Duplicate approve/deny logic for `onboarding_applications`** — implemented twice:
  once in `api.php:932-1078` (`admin_review` action — sends HTML/SMTP email, promotes
  approved sellers/buyers into `sellers`/`buyers` tables) and once in
  `admin/index.php:85-124` (raw PHP `mail()`, plain text, **does not promote** to
  `sellers`/`buyers`). This is a functional gap, not just duplication: an admin who
  approves via `admin/index.php` gets a different (weaker) outcome than one who approves
  via the in-SPA admin panel (`assets/js/app.js:3956`). **Actionable**: pick one canonical
  approval path; the other is effectively dead/divergent code.
- **`crop_prices` action, `price_review_list` action, `price_review` action,
  `test_email` action** — dead per § Gaps above (no caller found).
- **Historical dead district-coordinate table** — already removed but documented as a
  cautionary comment at `ussd/menus.php:123-127`; nothing to clean up now, just don't
  reintroduce it.

Not independently confirmed as dead (would need a JS-level unused-export scan, out of
scope for a grep-based pass): individual functions inside `assets/js/app.js` (3563 lines)
and `ussd/helpers.php` (200 lines, 6 functions all referenced from `logic.php`/`weather.php`
